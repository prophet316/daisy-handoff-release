**Talk to Claude. Your computer does the work.**

Nuff Said is made for Claude.
It's an independent project, not made by, affiliated with or endorsed by Anthropic.

It's one custom connector you add in the Claude app. After that, a conversation with Claude, including a live voice conversation on your phone, can hand real work to Claude Code on your own computer: start jobs, run threads, check progress, approve, retry, schedule, and stop everything.

### Read this first
This release ships with the command line and desktop control **on**, the way I use it.
- **What a job can do:** anything you can do at your keyboard, like running commands, changing or deleting files, opening apps, and clicking and typing on your desktop, with your logins.
- **Who can start one:** anyone with your connector URL, through their own Claude or the Claude API, and anyone who can change your connector on your Cloudflare account. A prompt injection in a web page or email can steer a job too.
- **What waits for your yes:** sends, posts, spending, deletes and access changes, unless you asked for them. The built-in desktop, email and publishing tools hold them in code, but a job with a command line can reach those apps another way. Everything else is an instruction to Claude. That lowers the risk but doesn't remove it.
- **The off switch:** answer no to the installer's question, or run `node install.mjs --no-power-lanes`. It's not a sandbox: code jobs still run Claude Code with its own command line.

Install it only on a computer you trust it with. Desktop control is Mac only for now.

### What's new in 0.9.1
- **A new name.** Daisy Handoff is now Nuff Said, and the download is `nuff-said.zip`. Daisy is still the default name of the worker on your computer. Your install folder, Cloudflare connector, database and background services keep their names, so `--update` finds your install and your connector URL stays the same.
- **What your yes unlocks stays yours.** The desktop gate's record of what it held, and a job's lane settings and message inbox, live outside the job folder, so a computer job can't change them. The approval card says what the gate held, every time, including a second stop from a run you already approved, and an old order file can't turn a charge back on, even after a reply or retry. A purchase card's items, total and address are what the job read off the order page, not something Nuff Said checked, and the card says so. A run an agent started, retried, replied to, messaged while it ran, or approved doesn't publish by itself; the publish waits for you.
- **Agents can't approve for you.** Every job, thread, schedule, routine, message, reply, approval, cancel and stop records who sent it. Your own Claude chat is recognized as you, by the Anthropic address it calls from. Scripts and agents that call the URL directly are labeled as agents: the connector refuses their approvals, publishing and sharing, and its run-command and desktop tools, and what they start (including ordinary jobs with a command line) is marked as theirs, never as your approval. A lead agent you turn on can approve, with limits: it can't approve sending a held email, and its approval never lets a desktop job send, post, buy or pay, even one your own request allowed or a restart left waiting. An address counts as one you gave only if it's in your own words, never in a job or note an agent wrote. It's a check on where the call comes from, not a login: anything that reaches your connector through Anthropic, including the Claude API, counts as you, and so could a job that starts its own Claude session with your account's connectors, so the URL stays a password. SECURITY.md has the details.
- **Job output is labeled as untrusted in your chat.** Tools that read jobs back return their text between `<job-output>` tags under a label that says it's untrusted job output, never instructions from you. Tools that act on a job (approve, cancel, retry, reply, publish, force kill, and the "which one?" list) quote the job's title the same way. A fence tag planted inside the text, including look-alikes, is taken out, and a job an agent made says so. Claude is told never to run commands, approve, publish, resume or use the desktop because job text asks. It's an instruction to Claude, not a lock: SECURITY.md says what that means.
- **Update in place.** `node install.mjs --update` keeps your keys, connector URL, Cloudflare connector and database, answers, job folders and settings. Nothing to redo in Claude.
- **Change every key at once.** `node install.mjs --rotate-keys` first deploys the connector code again from your install folder and removes any secret Nuff Said doesn't set, so code someone planted never gets the new key. Then it changes the connector key, so the leaked URL stops working right away, and then lists every schedule, routine, running job and job waiting to run with who set it up, so you can clear anything planted while the URL was out. Then it changes the worker and lead agent keys and restarts the worker. Jobs you chose to stop stay stopped, and a running desktop or screen job waits for your yes. It can't undo what someone did with the URL, and a code job has its own command line even with the command line switch off, so whichever way it was set, SECURITY.md lists what they could reach (your Cloudflare sign-in, your Claude sign-in, GitHub and other tokens) and how to take each back, ending with a second key change after the Cloudflare sign-out.
- **Phone notifications are off unless you say yes.** The bell answers Claude Code's "I am using this for local development" warning each time it starts, so the installer asks, says so in the question, and takes no for an answer: pressing Enter, `--yes`, and an update from 0.9.0 all leave it off. `--bell` turns it on, `--update --no-bell` off again.
- **Off switches.** `--update --no-lead-agent` turns the lead agent off.
- **The job card shows a held email before you approve it.** The card shows who made the job, and the email's sender, recipients, subject and body above its Approve button. In a list, a job holding an email gets Open instead of Approve. The card's Reply and Follow up buttons name the job by its id, never by a title an agent could have written.
- **Fewer Cloudflare requests when idle.** The supervisor checks for commands every 2 seconds while a job is queued or running, for a minute after a command, for 10 minutes after a stop or force kill, and while a job process is still alive on the Mac, and every 15 seconds otherwise. Measured on a Mac against a test connector: about 14,400 requests a day idle, down from about 51,800, out of the free plan's 100,000. The README's Cloudflare requests section has the numbers.
- **Keys written as is stay out of finished jobs.** The redactor that cleans live reads now also cleans the files and result stored when a job ends, the phone notification, and a held email. A held email that carried a key can't be sent. It catches exact copies only: a job that encodes a key first isn't caught.
- **Your own time zone.** Schedules and the times Claude reads out use your Mac's time zone, not US Central Time. `--time-zone NAME` picks another.
- **A doctor.** `node doctor.mjs` finds the common problems, says what to do about each, and saves a report with your keys removed. It only sends your key to the connector your install deployed.
- **Desktop control stays out of the Claude app** unless you name it, and treats express checkout buttons like "Buy with 1-Click" as the step that charges money.
- **A stopped update is safe to run again.** If an update stops partway, for example at the Cloudflare sign-in, running `--update` again keeps your answers (the command line switch, the lead agent) and your connector URL. The doctor and `--rotate-keys` say to do that.
- **A health check without false alarms.** On a stock install, the optional email alarm and desktop control (when it's off or CuaDriver isn't installed) no longer show up as problems.
- **The phone bell's folder is trusted at install.** On a new Mac, Claude Code asks whether to trust the folder the bell runs in, and nobody is there to answer. The installer now records that trust for you.
- **Help for first-time installers.** A troubleshooting page, a step-by-step manual install, an "Install problem" issue form, and a README that lists everything you need and what it costs before you start.
- **How to hear about updates.** The README explains how to get told about new releases and security fixes, and how to update.

### Install (Mac)
1. Download `nuff-said.zip` below and unzip it.
2. In Terminal, in that folder: `node install.mjs`
3. In Claude on the web (claude.ai) or the desktop app, go to Customize > Connectors, click + Add, choose Add custom connector, name it Nuff Said, paste the URL it copied, and click Continue. Claude shows the authentication settings it detected; click Continue again. Under Authentication choose No sign in, leave Request headers empty, and click Add ([Get started with custom connectors](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)).
4. If Nuff Said isn't on for the chat, tap + > Connectors and turn it on. Then start voice and say: "Check updates with Daisy." You're still talking to Claude; the name tells Claude to use your connector.

Needs macOS 13 or newer (14 for desktop control), a Claude Pro or Max plan with Claude Code signed in on this Mac, Node 22.13 or newer, Apple's Command Line Tools (for phone notifications and the blue glow), and a free Cloudflare account. The README's What you need section has the details and costs. Try `node install.mjs --dry-run` first if you want to see everything it would do.

### Updating from 0.9.0
In the new release folder run `node install.mjs --update`. It keeps your keys, so your connector URL stays the same and there's nothing to redo in Claude. Schedules made under 0.9.0 used US Central Time; after the update they use your time zone, so check their times. The update asks whether to keep phone notifications; they stay off unless you type yes.

### What's tested in this release
GitHub Actions was blocked on the account while 0.9.1 was made, so none of this ran on GitHub, and nothing ran on Windows. Everything below was run by hand on one Mac (macOS 26.4, Node 22.23).
- On a dry-run install, with the command line and desktop control on and off: `./test.sh gate` (the desktop gate, host lane, command line switch, who-sent-it, shell lane, redaction, bell, bell startup prompts and time zone self-tests) and `test/verify-dry-run.mjs`.
- `test/run-state.mjs`, inside `./test.sh gate`: the hold record, lane settings and message inbox live outside the job folder; an agent's retry doesn't publish; a second hold from an approved run shows what approving unlocks; an old `purchase.json` unlocks no charge, including after a reply or retry; an agent's message while a job runs holds its publish; a lead agent's approval sends no email and unlocks no send, post, buy or charge, even one your own request allowed; only your own words count for email recipients; held emails, a job's files, its result and its phone notification are redacted.
- `test/sender.mjs`, inside `./test.sh gate`: who sent each call, and what agents and the lead agent are refused, including a held email and an agent's retry, reply or mid-run message on a desktop or screen job; the job card shows a held email before Approve, and its buttons never put a job title in your message or Claude's; every tool that reads job text back returns it fenced and labeled, every tool that acts on a job quotes its title fenced, and a planted closing tag, including look-alikes, can't break out; job titles and schedule, routine and thread names are stored without control characters; after a worker restart a running desktop or screen job waits for your yes, an agent can't approve it, and the lead agent's approval can't send.
- `test/kill-session.mjs`, inside `./test.sh gate`: stop and force kill find a job's process by its session, without Python, after the process cleared its environment and its parent died.
- `test/poll.mjs` runs the real supervisor against the connector code on the Mac: it polls slowly when idle and fast after a command, a stop, a force kill, or while a job process is still alive, and run_command isn't refused on a working Mac.
- `test/doctor-no-leak.mjs` and `test/update-resume.mjs`: an update that stops partway keeps your answers on the next try and says the old settings are still live; `--no-lead-agent`, `--no-bell` and `--bell`; the bell is off with `--yes` and with Enter at its question in a real terminal; an unclear answer at either install question is asked again, and "nope", "no thanks" and "No." mean no; conflicting flags stop before any question; a real install on Windows is refused; `--rotate-keys`, with a stand-in for wrangler, deploys the clean code and removes a stray `OWNER_CIDRS` secret before it stores any key, changes no key if that deploy fails or there's no terminal, and says to do the leak cleanup whichever way the command line switch was set; its list shows names with terminal escape sequences as plain text; with the Command Line Tools missing, turning phone notifications on is stopped and the doctor says what the tools are for; the Cloudflare account name is printed after the sign-in; `--uninstall` of an install never deployed gives no Cloudflare steps; an update after an unfinished first install records no earlier version.
- `test/overlay-build.mjs` builds the blue glow helper for this Mac's chip, runs it, and checks that a missing toolchain or a failed build leaves the install finished.
- The installer dry run for macOS and, written as Windows files on the Mac, for Windows (`--platform win32`, checked by `test/verify-dry-run.mjs`). The Windows worker itself didn't run.
- Time zones tested in Chicago, Los Angeles, London, Kolkata, Sydney, Tokyo and UTC.
- Against throwaway Cloudflare connectors, deleted afterwards: update in place, and `--rotate-keys` with other code deployed over the connector first and an `OWNER_CIDRS` secret set, as someone with your Cloudflare sign-in could. Cloudflare's version history showed the clean code deployed, then the stray secret removed, then the new connector and worker keys stored, so the planted code never ran with a new key. Its route was gone afterwards, the new URL answered, and the old one got HTTP 404. An earlier run's list showed a job an agent had queued. The D1 query in SECURITY.md for the connector's list of commands ran there too. The worker restart step of `--update` and `--rotate-keys` wasn't covered, and those runs didn't include Claude or a phone. `--update --no-lead-agent` removing the lead agent key from Cloudflare ran only as dry runs and offline tests.
- Not yet run for this release: a fresh install on a new Cloudflare account and a new Claude account, from the zip through a voice job and a phone notification.

### Known limits
- Mac today. The Windows worker is in testing and isn't in this release; the installer refuses a real install on Windows.
- Jobs use your Claude plan's normal Claude Code usage limits. Up to 3 run at once, and a job has no time limit (a runaway guard stops it after 24 hours).
- Computer use (operating your desktop) is macOS only.
- Turning the command line and desktop control off is not a sandbox: code and design jobs still run Claude Code with its normal tools.
- Pro and Max only for now. On Team and Enterprise, an admin (an Owner, or on Enterprise someone whose role can manage connectors) adds a custom connector for the organization and people across it can then connect to it, so don't add yours there.
- Phone notifications use Claude Code channels, a research preview from Anthropic. The bell's channel isn't on Anthropic's approved list, so the bell starts Claude Code with its developer flag for channels. That flag shows a warning Anthropic meant for people testing their own channels, whose answer is "I am using this for local development", and it comes back every time the bell starts. The installer says so in its question, and phone notifications stay off unless you say yes; if you do, the bell picks that answer for you each time it starts. Claude Code decides when to push, and Anthropic says it can skip a push when it detects that you're active. To turn the bell off: `node install.mjs --update --no-bell`. A Claude Code update could stop notifications until Nuff Said is updated. Jobs keep running either way.
- A free Cloudflare account allows 5 cron triggers in all, and Nuff Said uses 1. If the deploy fails mentioning cron triggers, TROUBLESHOOTING.md says what to do.
- Your connector URL is a password, and access to your Cloudflare account is access to your Mac: anyone who can change your connector or its database there can run commands on it. Read SECURITY.md before you install.
