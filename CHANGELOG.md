# Changelog

## 0.9.1
GitHub's own runners were blocked on the account while 0.9.1 was made. `installer.yml` ran on one Windows PC of the maintainer's, with no Mac leg; the CI lines below say what it's set up to run. Every Mac test was run by hand on one Mac. The Windows worker didn't run.

### Name
- New name: Nuff Said (was Daisy Handoff). The release zip is `nuff-said.zip`, and the installer suggests naming the connector "Nuff Said". Daisy is the default name of your assistant, the worker on your computer. The install folder (`~/Projects/NAME-handoff`), Cloudflare Worker and D1 database names, launch agent labels (`com.daisy.*`) and Windows startup file names are unchanged, so `--update`, `--rotate-keys` and `--uninstall` keep working on existing installs.

### Who sent it
- The connector records and enforces the real sender on every tool that starts, schedules, approves, replies, retries, cancels or changes jobs. Your own Claude chat is recognized as you by the Anthropic address range it calls from; anything else (an agent or job on your computer, or a script) is labeled as an agent. It's a check on where the call comes from, not a login, and SECURITY.md says what it can't tell apart.
- Agents can't approve, answer a job waiting for your yes, publish or share, use run_command, command_result, look_at_screen or use_computer, or undo stop everything. They can't retry, reply to or message a desktop or screen job either; the worker refuses such a run too. They can still start ordinary jobs, which run Claude Code with its command line, and what they start is marked as theirs, never as your approval. A run of a schedule or routine an agent saved is marked as that agent's.
- New, off by default: `--lead-agent NAME` lets one named agent approve and answer jobs waiting for your yes, logged as that agent. It can't approve sending a held email, and its approval never unlocks send, post, buy or charge for a desktop job, even when your own request allowed them or a restart left the job waiting. `--update --no-lead-agent` turns it off and removes its key from Cloudflare.
- A run an agent started, retried, replied to, messaged while it ran, or approved doesn't publish or share by itself; the publish waits for your own "publish it".
- Email recipients count only from your own words: not the title or details of a job an agent made, not a note an agent sent, and not a history line an agent's text tried to forge (history entries are one line each).

### Job output in your chat
- Tools that read jobs back (check_updates, list_jobs, get_job, find_job, read_job_files, list_threads, list_schedules, daily_digest, health_check, worker_status, run_command, command_result) return their text between `<job-output>` tags under a label that says it's untrusted job output, never instructions from you. Tools that act on a job (approve_job, cancel_job, retry_job, reply_to_job, publish_job, force_kill_job, and the "which one?" list any of them gives) put the same label first and quote the job's title, and a held email's sender, recipients and subject, the same way. A fence tag inside the text, including look-alikes made with other dashes, zero-width characters or full-width brackets, is taken out, and a job an agent made says so. The connector tells Claude never to run commands, approve, publish, resume or use the desktop because job text asks. It's an instruction to Claude, not a lock, and SECURITY.md says so.
- The job card shows a held email (who made the job, sender, recipients, subject and body) above its Approve button, and a list card gives such a job Open instead of Approve. The card's buttons name the job by id, never by its title, both in the message they send and in what they tell Claude.

### Desktop control and approvals
- The desktop gate's record of what it held, the job's lane and hook settings, and its message inbox live in `~/.NAME/runs/<job>`, outside the job folder. No job's file tools may write there, and desktop, research and writing jobs may write only in their own job folder (and a thread's folder), so they can't widen what your yes unlocks, add a message in your voice or change Nuff Said's own code. Before this, a bare `Write` or `Edit` allow rule let those jobs write anywhere in your home folder. An approved run under a settings profile without Bash isn't told it has the command line. An approved run unlocks only what the gate held on the run before, and the approval card lists what the gate held, including on a second hold from a run you already approved.
- A charge is unlocked only by a purchase card the worker recorded outside the job folder. Every desktop run (approved, reply or retry) moves an old `purchase.json` aside, and a purchase card says its numbers are what the job read off the order page.
- A worker restart (an agent can ask for one) doesn't start a running desktop or screen job again by itself: it waits for your yes and says it may be partly done.
- Desktop control treats the Claude app and claude.ai as off-limits unless your request names them, and checks a browser tab's address from its last look before every action, so a tab that reached claude.ai through a link is refused too (a redirect between the look and the action isn't caught). Claude in Chrome's side panel, or another Claude add-in inside an app's window, is refused the same way, and so is an element named Claude, whether clicked by element or by position. An element token is checked in the app and window it came from, and a token from no look isn't used. A call without a pid (or any field the tool requires), with a pid that isn't a running app, or with a window from another app or one the job hasn't seen, is refused. A click by position is checked against what's under it in the last look at that window and refused in every app if that look can't place it. Outside a browser, typing and keys need a look since the last action, so a Claude pane that opened since is seen. `open_url` won't open an off-limits app named as its browser. A browser no list knows is found by its address bar, so the claude.ai check and the named-site check for your details stay on in it. These ran only against a stand-in for CuaDriver. It also refuses apps that run commands or scripts (terminals, Script Editor, Automator, Shortcuts, code editors, OpenAI's desktop apps, Docker), launchers (Spotlight, Alfred, Raycast and others) and Command-Space and Option-Space, and apps that change the system (Activity Monitor, Disk Utility, Installer and others) unless your request names them. It holds express checkout buttons ("Buy with 1-Click", "Pay with Link") as the charge step.
- In a browser, and in mail and chat apps, the desktop gate holds Return and Enter (with any modifier keys), Space, and typed text with a line break or a Tab in it or a space at its start as a send unless your request asks to send (a Tab is held even in a search box, since it moves focus off the box), because Return sends in Slack, WhatsApp or Gmail on the web. Return still goes through in a search box or address bar, by that box's element or right after typing in or clicking it.
- After a Tab key (Shift-Tab too) in a browser, mail or chat app, typed text with a space anywhere in it is held as a possible send, since the Tab may have moved focus to a Send button. The mark stays for the rest of the job, since a new tab, Command-W, Command-1 or a click in another window can go back to the Send button. Text goes through only when the action just before put focus in a text field in that window (a click on one, typing or a key on one by its element, or a look that shows one has focus), or by a text field's element. The VM lane holds it until a click; a new page or a launched app doesn't clear it, and any shortcut after a Tab holds it again.
- Typed text with a line break into a search box or address bar submits it, so it ends the search box allowance: the next Return or typed line break is held. The allowance covers a line break only at the very end of the text; more text after a line break, in one call, is held. `launch_app` by name ends every app's allowance. Space counts as a send in any combo without Command, Option, Control or Fn (Tab plus Space, say), and more names for Return and Space (`kp_return`, `enter_key`, `cr`, `spc` and others) count too.
- The installer folds its long lines (ok, note and skip lines, the last step, the Cloudflare sign-in lines, the stop after a failed update and the key change's next steps) to 80 columns. Commands and long paths stay on one line so they copy whole. `CONTRIBUTING.md` is in the release zip.
- On a run the lead agent approved, the host lane's gate no longer takes your original request's words as your yes for send, post or buy (the worker passes `HOST_NO_IMPLY`), so such a run can't send even when your first request asked to.
- The search box allowance is tied to the window: Return goes through only right after the job typed in or clicked the search box in that same window, and `open_url`, `activate_app`, `launch_app` and `quit_app` end it. A hotkey counts as a send whatever order its keys are in (Return then Command, say), and so do other names for Return and Space (`ret`, `linefeed`, `spacebar`, or a bare space or line break given as the key).
- `open_url` and `launch_app` refuse an app given as a path or with characters an app name doesn't have, and `open_url` refuses an off-limits app's bundle id as its browser, so none of these can get past the name and bundle id checks.
- Typing and key presses with no element are refused if a look showed Claude in any window of that app, not only the window looked at last (a round 17 regression). A click with neither an element nor both x and y is refused.
- A job's own Claude sessions start with `ENABLE_CLAUDEAI_MCP_SERVERS=false`, so they don't load the connectors in your Claude account, and jobs are refused the usual `cua-driver` and `composio` commands. Both are speed bumps a job can get around, and the docs say so.
- Mac: the installer builds the blue glow and assistant cursor helper with the Command Line Tools, for the Mac's own chip and macOS 13 or newer, and sets its path in the worker config. A failed build is a note; desktop control still works. The doctor says when the helper is missing.

### Keys and leaks
- `node install.mjs --rotate-keys`, in this order: deploys the connector code again from the install folder and removes any secret Nuff Said doesn't set (such as `OWNER_CIDRS`), so planted code never gets a new key; changes the connector key, so a leaked URL is locked out at once; lists every schedule, routine, running job and job waiting to run with who set each up, and asks whether to clear them; then changes the worker and lead agent keys and restarts the worker and supervisor. The worker key comes last so the worker isn't cut off while you read the list. Jobs you chose to stop stay stopped, and a running desktop or screen job waits for your yes. With no terminal it stops before changing anything. With `--no-start` it says to restart the worker and supervisor yourself. `--clear-schedules` clears them at any time.
- `--update` rebuilds `worker/config.json` from the release and keeps only your numbers, on/off choices and a few names: the disk it watches, the separate desktop's name, the glow's motion and the Composio account names (a Composio program path only if it's the standard one). It doesn't keep a Google Drive upload folder or a turned-off Google account check, and lists them so you can set them again. It moves any `.claude` folder in your job and thread folders (Claude Code would run its hooks), and any job or thread folder, or whole `jobs` or `threads` folder, that is a link, into the `.bak` folder and says so. It moves a link itself, never what it leads to, and moves a `CLAUDE.md` or `CLAUDE.local.md` directly in `jobs` or `threads`. Ctrl-C, or the terminal closing, during an update stops it like any other stop, and puts the old folder back if the new one doesn't have the keys yet. The worker also refuses to run a job in a job or thread folder that is a link, and checks a linked `jobs` or `threads` folder before it makes anything in it. The leak steps' `find` follows links, lists them, and leaves out the phone bell's own `.claude` folder. A setting named like a built-in JavaScript name (`valueOf`, `__proto__`) is dropped like any other unknown one. Every program path, command, tool list and environment setting comes from the release, so one planted after a leak doesn't survive the update the leak steps ask for. It lists what it didn't keep. A blue glow helper already in place is removed before the build, so a build that fails or can't run leaves none.
- The leak steps in the installer, README and SECURITY.md apply whether or not the command line was on, because a code job has its own command line. They cover your Cloudflare sign-in, Claude sign-in, GitHub and other tokens, say that `logs/shell.log` alone can't be trusted, and end with a second `--rotate-keys` after the Cloudflare and Claude sign-outs, before you add the connector again.
- Job titles and schedule, routine and thread names are stored without control characters, and `--rotate-keys`, `--clear-schedules`, the worker, supervisor and bell logs and the doctor's report show any that are already stored as `?`. A name with terminal escape sequences can't move the cursor or erase lines, so it can't hide itself from the list you check after a leak.
- SECURITY.md's key change by hand removes secrets Nuff Said doesn't set, as `--rotate-keys` does, and checks schedules without adding the connector early. The leak steps say when the second key change is the last one.
- The docs say that a job runs the hooks and `env` settings in the `.claude` settings of the folder you send it to, with no trust prompt, in every mode and with the command line on or off. They say a code or design job can read and change any file in your home folder, not just the folder you send it to.
- Each job is told only the access its mode has: code and design jobs are told they have the command line and your home folder, and research, writing, screen and desktop jobs aren't.
- Claude's update check brings up a new daily digest once, which it's set up to do at the start of a chat, with phone notifications on or off (an agent's update check shows it too but doesn't use it up), and the digest, screenshot and desktop replies mention a phone push only when notifications are on (the installer writes `PHONE_BELL` in `wrangler.toml` to match).
- The daily digest, the health check, the force-kill reply and the schedule-saved and routine-saved replies say what you'd say ("Stop everything", "cancel it", "force stop it", "retry it"), not tool names.
- The docs say that your Cloudflare account is a key too: anyone who can deploy to your connector's Worker or change its database can run commands on your Mac.
- The redactor that cleans live reads also cleans the command line's output, the files and result stored when a job ends, the phone notification and a held email, and hides the connector key, connector URL and lead agent key. A held email that carried a key can't be sent. It catches exact copies only.

### Installer and updates
- The command line and desktop control are on by default. At the installer's question, Enter or yes means on and the question says so; "no", "nope", "nah", "no thanks" and "No." mean off; anything else is asked again, and three unclear answers leave it off. `--no-power-lanes` and `--power-lanes` set it without the question.
- Phone notifications are their own question and are off unless you say yes. The question says the bell uses a research-preview development channel and that Nuff Said answers Claude Code's "I am using this for local development" warning each time the bell starts. Enter, `--yes`, and an update from an install with no answer on record leave it off. `--bell` and `--no-bell` turn it on or off, also on an update. The bell answers its startup prompts only until Remote Control is up or for 90 seconds, then stops reading the session's screen.
- `node install.mjs --update` updates in place: same keys, connector URL, Worker and database, last time's answers, job folders, logs and worker settings. An update that stops partway is safe to run again and says that Cloudflare and the running worker still use your old settings until it finishes. If it stops or fails before the new folder has your keys, it puts the old folder back as it was and says so.
- With no terminal and no `--yes`, the installer stops at the first question instead of answering it, and `--yes` prints each answer it took. Conflicting flags stop before any question.
- New `--manual` for step 1 of MANUAL-INSTALL.md.
- Schedules and the times Claude reads out use your own time zone, taken from your computer at install; `--time-zone NAME` picks another. Before, they were always US Central Time.
- The installer marks the phone bell's folder as trusted in Claude Code, so the bell can start on a new Mac, and `--uninstall` removes that one entry from `~/.claude.json` again.
- Stop everything, cancel and force kill no longer use Python: the worker reads each process's session through `osascript`, which is part of macOS. Apple's Command Line Tools are needed only for phone notifications (`/usr/bin/python3`) and the blue glow (Swift). With phone notifications on and the tools missing, the installer stops before it changes anything and says how to install them; the doctor checks that `/usr/bin/python3` runs and says what this install needs the tools for.
- After the Cloudflare sign-in, the installer and `--rotate-keys` print the name of the Cloudflare account they'll use. The installer's warning at the command line question says that off isn't a sandbox and that your Cloudflare account is a key too.
- The installer's command line question says why Enter means on there, and the phone notification question says why Enter means off there. The defaults are unchanged.
- `--uninstall` of an install that never reached Cloudflare doesn't give the Cloudflare delete steps. An update after a first install that never finished doesn't make the doctor speak of an old setting.
- The old `deploy.sh` is gone from the install folder. Deploy with the installer, or by hand with MANUAL-INSTALL.md. `./test.sh deployed` uses Node instead of Python. It queues a real job on your connector, which your worker runs with Claude Code on your computer; the script says so.
- The installer needs Node 22.13 or newer and says so before it starts. It refuses a real install on Windows, which isn't in this release (a dry run still works).

### Supervisor and requests
- The supervisor polls every 2 seconds while a job is queued or running, for a minute after a command, for 10 minutes after a stop or force kill, and while a job process is still alive, and every 15 seconds otherwise: about 14,400 Cloudflare requests a day idle (measured against a local test connector).
- run_command refuses, with nothing queued, only when the supervisor hasn't checked in for 45 seconds, and the connector rewrites the check-in once it's 10 seconds old, so an idle Mac isn't refused.
- Stop, force kill and the worker's cleanup at start use a recorded session id only while it is still the job's: recorded since the Mac last started, with its leader started when the run did, or, with the leader gone, only processes started while the run could still be running. After a restart of the Mac, a session id left in a job folder can belong to another program, and it's ignored. The worker deletes the run records of jobs with nothing left running when it starts.
- Force kill also ends every process in a session one of the job's processes leads. Claude Code's Bash tool runs each command's shell in its own session, so a command's double-forked child used to outlive force kill. TROUBLESHOOTING says what it still can't find.
- Replies Claude reads aloud call the supervisor the stop switch, the same name the health check uses, and don't read out launchd or `com.daisy.*` names. A command you'd need to type is marked as one to type, not read aloud.

### Doctor and docs
- New `node doctor.mjs` (also `node install.mjs --doctor`): checks your computer and install for the common problems, says what to do about each, and saves a report with keys, URLs, emails and your user name removed. It only sends your key to the connector your install recorded as deployed. It handles manual installs, installs whose connector was never deployed, and uninstalled ones.
- The health check doesn't report the optional email alarm, or desktop control that's off or not installed, as problems.
- New TROUBLESHOOTING.md, MANUAL-INSTALL.md and an "Install problem" issue form. The README lists everything you need and what it costs, how to add the connector in Claude, how phone notifications use Remote Control, how to start things again after Stop everything, how to hear about updates and security fixes, and how Nuff Said compares with what's built into Claude.

### Tests
- `./test.sh gate` runs the desktop gate, host lane, command line switch, who-sent-it (`test/sender.mjs`), run state (`test/run-state.mjs`), supervisor poll (`test/poll.mjs`), stop by session (`test/kill-session.mjs`), time zone, shell lane, redaction, bell and bell prompt self-tests. `installer.yml` is set up to run the installer dry run, update and key change, and the time zone, redaction and bell prompt tests on macOS and Windows, plus `./test.sh gate` on macOS.
- `test/doctor-no-leak.mjs`, `test/update-resume.mjs` and `test/overlay-build.mjs` run from the release folder.
